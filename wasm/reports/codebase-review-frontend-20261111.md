## 1. Scene replacement can complete after a newer replacement or destruction

**Correctness risk established from source; high confidence in missing protection, runtime reproduction pending. Effort M.** `PlateView.tsx:352` starts `setObjects` without awaiting or cleanup. `PlateScene.ts:1198` mutates shared maps across awaits for each object's regular and viewer meshes (`1209`, `1290`), then removes entries absent from its own input (`1353`). No invocation generation or destroyed check protects these continuations. Destruction sets `isDestroyed` at `PlateScene.ts:3032`, but `setObjects` never checks it. Trigger: slow mesh retrieval overlapping a later import/delete/undo refresh, or unmount during retrieval. An older call can reinsert deleted objects, remove newer objects, or allocate geometry after cleanup. This is an existing architectural risk, not established as introduced by the recent interaction changes.

Smallest fix: generation-check every async continuation before mutation and invalidate the generation on destroy; publish the mesh revision only when the accepted update completes (`PlateView.tsx:353` currently publishes immediately). Keep this within the existing `setObjects` module interface. Validation: deferred `getMesh`/`getViewerMesh` adapters resolve A/B out of order, including destruction; assert only B remains and late allocations do not survive. The existing callbacks are a real test seam; no new abstraction is required.

## 2. Transform refresh repeats viewer serialization and full geometry comparisons

**Performance hypothesis with confirmed repeated work; high confidence, no measured speedup. Effort M.** Every `refreshObjects` clears the entire viewer cache (`plateStore.ts:230–231`). Batch instance transforms call it even though local vertex buffers are unchanged (`plateStore.ts:372–380`). `PlateScene.ts:1249–1266` scans regular positions and indices; `1290` fetches viewer data; `1320` scans positions again per volume per instance. Native `Engine.cpp:1985–2004` copies each volume mesh and merges it to construct the viewer response. Thus moving a small instance can serialize unrelated objects and scan large unchanged meshes; copies of one object repeat the volume comparisons. Regular mesh caching means this is not a claim that both native representations are fetched on every update.

Smallest fix: retain viewer buffers for instance-only transforms and rename, invalidating the affected object for geometry/volume edits and all objects on project restore. Track a geometry revision so scene transforms skip buffer comparisons. Validate with a dense object plus many instances: count getMesh calls/bytes, compare refresh-to-final-frame latency and main-thread CPU before/after a translation; verify cut, repair, part transform and undo still invalidate correctly. Existing geometry reuse is useful and should be retained. Architectural cost predates or is independent of the accepted group gizmo fix; the new batch action exercises it.

## 3. Visible idle Prepare submits a frame continuously

**Confirmed scheduling behavior; performance hypothesis for user impact. High confidence. Effort M.** `PlateScene.ts:2588–2615` reschedules animation whenever visible, updates controls and selection bounds and renders on every callback, even with no changes. `1458–1475` scans object meshes for selection bounds on each frame. Visibility/document guards already stop hidden rendering. Preview instead coalesces explicit draw requests (`orcaPreviewModule.ts:381`), so this finding applies to Prepare rather than both viewers.

Smallest fix: use a dirty flag with a short continuation while damping or an active gesture needs it; invalidate on camera, geometry, theme, resize, labels and asynchronous asset changes. Benchmark idle draw count, CPU/GPU time and battery-relevant utilization on physical hardware; check orbit damping, cut preview, paint cursors, group gizmos, HTML label paint completion and theme updates. Do not infer savings from headless FPS. This is an existing architectural opportunity.

## 4. New box selection has a costly empty-hit worst case

**Performance hypothesis in accepted uncommitted implementation; high confidence in complexity, magnitude unknown. Effort M.** `boxSelection.ts:19–51` rejects meshes against the full camera frustum, then clips every triangle against the rectangle planes with fresh vector/array allocations. A small rectangle missing a dense mesh that is elsewhere on screen still visits every triangle. `PlateScene.ts:171` invokes this synchronously on release, so this can delay selection and the next UI frame. It runs once per completed drag, not per pointer move; the existing exact triangle clipping preserves important selection semantics.

Smallest fix: add a conservative rectangle-frustum bounds rejection before triangle clipping, preserving clipping as the final test. Benchmark a tiny empty rectangle beside a visible million-triangle model, a true hit and many instances; capture release-handler duration and allocation/GC, and retain near-plane, perspective, orthographic and partial-triangle cases from `wasm/tests/node/box-selection.test.mjs`. Consider a spatial index only if the broad-phase benchmark still demonstrates a problem.

## 5. Preview load is synchronous native parsing on the UI thread

**Confirmed blocking path; performance hypothesis for severity. High confidence. Effort L for off-thread parsing, S for instrumentation.** `previewStore.ts:97–101` declares an async action but calls synchronous `orcaPreviewModule.loadGcode`; that function directly invokes native `loadGcode` (`orcaPreviewModule.ts:253`). `preview/preview.cpp:599` runs GCodeProcessor synchronously and `620–626` converts the result before rendering. `PreviewView.tsx:237` calls this from the UI effect. Large G-code therefore blocks interaction and prevents the loading state from painting during parsing. Slicing in a worker does not remove this separate Preview cost. Existing borrowed MEMFS bytes, processor lifetime scoping, WeakRef identity and draw coalescing already address other costs and should not be reported as missing.

Smallest next step: instrument parse, conversion and GPU upload separately using existing `wasm/preview/benchmark_preview.mjs` and `wasm/tests/app/preview-performance.mjs` with representative large files, recording long tasks and load-to-first-frame. If parsing dominates, move processing/conversion to a worker adapter and transfer the native viewer input; account for serialization costs and keep WebGL ownership explicit. A yield before parsing may expose a loading indicator but cannot make parsing responsive. No worker-compatible future interface is assumed here. This is a pre-existing architecture constraint.

## 6. History selection restoration is ambiguous and omits group selection

**Confirmed selection identity defect by source; useful feature gap for group restoration. High confidence. Effort S/M.** Capture stores both object index and name (`historyStore.ts:323–338`), but restoration first selects the first matching name (`173–188`) and only uses index if no name matches. Trigger: select the second of two imported objects with the same name, change it, then undo/redo; native IDs are recreated, and restoration can select the first object. The snapshot interface also holds only one instance (`history/types.ts:6–12`); restoration calls `selectObject` (`historyStore.ts:198`), which clears extras (`plateStore.ts:290`). A group transform can undo its geometry correctly while losing the group needed for the next edit. Existing group-transform QA reports validate geometry undo/redo; they do not establish full selection restoration.

Smallest fix: prefer the captured ordered object/instance location with validation for same-project snapshots, using name only as a fallback. Extend that existing snapshot interface with ordered instance references for extras and restore them together after native IDs are recreated. Validate duplicate-name objects, two instances of one object, a group across objects, deleted members and volume selection through undo/redo. This deepens the current history module rather than distributing remapping knowledge into gesture callers. Name ambiguity predates group work; group restoration becomes more useful with the accepted multi-selection features.

## Coverage and limits

Inspected Prepare mesh/cache/update lifecycle, selection outlines, group/body commit paths, box clipping, label creation/disposal, React effects and selected Zustand actions; Preview module lifecycle, native parsing, store actions and G-code text indexing; history selection capture/restore and import entry points. HTML object labels already allocate drawable DOM lazily, request static paint once and dispose sources/maps on rename/removal (`PlateScene.ts:1100–1138`, `htmlObjectLabel.ts:10–60`). The recorded label report includes eight-source lifecycle and fault-injection evidence, plus explicitly limited CPU samples (`html-object-labels-20261109.md:163`, `217`, `231`); it does not establish high-instance hardware scalability. No confirmed new label leak was found. G-code text uses a WeakMap line index and decodes a bounded display window (`gcodeLines.ts:14–47`), so whole-file text decoding on every scrub is not a valid finding.

Read existing HTML-label and recent group-transform reports; they provide prior QA evidence, not a fresh verification of this checkout. Recent release/box/group fixes were included rather than re-reporting their addressed symptoms. No numerical performance improvement is claimed. GPU driver behavior, touch/device gestures, production baseline equivalence, high-instance resource ceilings and end-to-end import responsiveness remain unmeasured. Native Preview internals were sampled to establish the UI-thread parse path; this is not a complete libvgcode/native renderer audit.
