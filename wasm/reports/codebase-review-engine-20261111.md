## 1. Cancellation cannot interrupt the new containment preflight

**Confirmed responsiveness defect; high confidence. Effort M.** `wasm/engine/Engine.cpp:2804` passes an empty cancellation callback to `project_mesh`; the pending cancellation flag is first checked at `:2849`, after all projections, `ensure_on_bed`, `Print::apply` and validation. `src/libslic3r/TriangleMeshSlicer.cpp:2451` forwards that callback into slab slicing, so the projection already has a cooperative cancellation seam. A cancel during high-triangle/many-instance containment must wait for this work to finish. This establishes an uninterruptible region, not a measured latency or a claim that every cancel is slow.

Smallest fix: check pending cancellation between instances/volumes and pass a cancellation-aware callback into projection. Handle cancellation at the outer slice boundary: the current `CanceledException` handler at `Engine.cpp:2905` only covers the later processing/export body. Preserve the cleanup guard's restoration of printability and queued-slice accounting. Validation: cancel after containment starts on a dense multi-instance model, verify bounded cancellation latency, restored flags and successful subsequent cube slice. Existing queued cancellation evidence does not test this phase.

## 2. Exact containment repeats triangle projection even for disabled instances

**Performance hypothesis backed by confirmed repeated work; high source confidence, gain unknown. Effort S–M.** `wasm/engine/Engine.cpp:2796–2812` projects every model-part volume for every instance before combining the result with the object's and instance's existing printable flags. `src/libslic3r/TriangleMeshSlicer.cpp:2451–2459` performs slab slicing and unions its results. Repeated instances therefore repeat geometry processing; explicitly nonprintable instances pay too. New containment correctness is valuable and supported by the 14 checks documented in `wasm/reports/bed-boundary-slicing-20261111.md`.

Smallest fix: skip projection for already nonprintable objects/instances first. Then measure whether a conservative transformed-bounds acceptance path is worthwhile for rectangular beds; retain exact projection for uncertain cases and concave beds. Do not substitute vertex-only containment. A later projection cache must account for mesh edits, volume transforms, instance rotation/scale/mirroring and bed/origin changes; a per-slice cache avoids persistent invalidation risks. Validation: time containment separately on 1/4/16 repeated dense instances, disabled instances, and concave beds; require the existing bed-boundary checks and unchanged eligible G-code. Existing engine-bench total slice timing does not isolate this newly added phase.

## 3. Repeat slicing discards native incremental state

**Useful feature / performance hypothesis; high confidence in discarded state, unknown payoff. Effort L.** `wasm/engine/Engine.cpp:2817` constructs a fresh local `Slic3r::Print` on each request and `:2836` applies the whole model/config. Native invalidation machinery exists at `src/libslic3r/Print.cpp:161–514`, including per-option and object-step invalidation. A second slice after a small setting change cannot reuse the preceding Print's computed state. This matters for interactive setting tuning and repeated export; it is not evidence that Model copying itself dominates, and mesh ownership must be inspected before calling every native model clone a full triangle copy.

Smallest investigation: benchmark identical repeats and one setting change against a controlled retained-Print prototype before committing to persistent state. If worthwhile, initially retain only one selected plate's Print, reset on project replacement/plate switch, and preserve existing cancellation cleanup. Validation: compare normalized G-code across fresh versus reused state after geometry edits, plate changes, printability changes, failed validation and cancellation; record retained heap/RSS as well as time. A blanket cache is unsafe without these invalidation checks.

## 4. Mesh RPC hides filesystem errors as successful empty geometry

**Confirmed contract defect; high confidence. Effort S.** `wasm/web/engine-worker.js:247–255` catches any `core.readFile(result.path)` error, substitutes an empty Uint8Array and returns `ok: true` with the native result's original vertex/triangle counts. If an exported mesh cannot be read, consumers receive internally inconsistent success metadata and lose the actual cause. No observed user incident is claimed; the error branch is explicit.

Smallest fix: let the read exception reach the worker's existing structured error handler. Validation: focused worker-bridge check with a rejected mesh-file read must receive `ok: false` and an error; successful transfers must retain their existing count/buffer contract. This is a narrow failure-path check, not a request for a new harness.

## 5. Mesh delivery creates several full representations and retains scratch files

**Confirmed allocation/serialization work; performance and long-session retention hypotheses. Effort M.** `wasm/engine/Engine.cpp:1983–2003` copies each volume into a temporary TriangleMesh, merges into an aggregate, then `:2030–2050` serializes it to `/out/mesh_<objectId>[_viewer].bin`. `wasm/web/engine-worker.js:250–255` reads a second byte representation and transfers it to the page. Transfer avoids another page-boundary copy, but does not eliminate native assembly or MEMFS serialization. The getMesh branch does not unlink scratch. Deleting objects with distinct IDs may leave obsolete files; this audit did not prove every deletion path's cleanup behavior, so sustained leakage remains unknown.

Smallest fix/investigation: measure getMesh allocation peak and serialization time on a dense multivolume object; consider writing header/offset-adjusted indices and vertices directly to the existing binary stream to remove the temporary merged mesh. Define scratch ownership before unlinking: public low-level callers may expect the returned path to remain readable. Validation: compare decoded vertex/index arrays, volume ranges and viewer transforms, including modifiers and mirroring; enumerate MEMFS scratch after repeated load/delete cycles. `wasm/tests/perf/engine-bench.mjs:88–89` times native getMesh calls but excludes the worker read/transfer path.

## 6. Large exports retain MEMFS G-code alongside the delivered buffer

**Confirmed memory cost; useful bounded-memory feature, unmeasured gain. Effort S–M.** `wasm/web/engine-core.js:299–303` reads the complete exported file into a Uint8Array and returns it without deleting the source. `wasm/web/engine-worker.js:492–499` transfers that array, leaving the MEMFS file in the worker. Default repeated slices reuse one pathname, so this alone is not evidence of an unbounded leak; custom output paths can retain multiple files. During delivery both representations exist. Native export also processes estimates (`wasm/engine/Engine.cpp:2863–2866`); preview interpolation is already disabled, so recommending its removal would duplicate completed work.

Smallest fix: define an opt-in consume-and-remove contract for wrapper-owned output files, preserving explicit caller-owned paths; remove scratch on failed/canceled exports only where ownership is established. Validation: large G-code export byte hash, subsequent download availability, caller-owned readFile behavior, and worker MEMFS/linear-memory high-water measurements. Freed WASM allocations need not reduce OS RSS. Streaming export is a larger design option only if the measured duplicate-buffer cost warrants it.

Recovery remained functional, with normalized cube parity, but these numbers are not a current-HEAD benchmark or isolated WASM-heap measurement. Short recovery plateaus cannot establish absence of leaks. The missing actionable measurements are current-candidate containment time/cancellation latency, complete worker mesh-delivery cost, and MEMFS/linear-memory attribution before/after large exports. Test thread counts 1/2/4/8 on a fixed candidate before changing concurrency defaults; `wasm/engine/CMakeLists.txt:49–57` already uses growable memory, mimalloc and a bounded preloaded pthread pool.

Parity coverage is explicitly bounded: `wasm/tests/parity/README.md:26–30` says historical macOS references predate portable ordering; the current browser smoke reference covers one cube with independently matched native output. Broader native equivalence for multi-material, modifiers, complex geometry and cancellation/reuse sequences remains separate work. Do not treat a missing historical reference or changed traversal ordering alone as a regression. No general geometry-kernel rewrite or vendored-library audit is recommended here.
