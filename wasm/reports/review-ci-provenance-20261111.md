## Manifest contract

`wasm/scripts/runtime-manifest.mjs` creates and verifies `runtime-manifest.json` per engine, preview and STEP directory. Version1 records source fingerprint, dependency-content fingerprint, flags/architecture and SHA256 per runtime JS/MJS/WASM/license file. Paths in manifests are relative; no host paths or secrets are recorded. WASM magic and required nonempty assets are checked. Source fingerprints cover C++ source, headers, bundled dependency source, CMake files, version.inc and dependency/build scripts, including modified working files independently of git HEAD. UI TypeScript/CSS edits do not require expensive runtime rebuilding.

Build scripts capture ORCA_BUILD_SOURCE before compiling and refuse to stamp if these inputs changed during the build. STEP also fingerprints OCCT_PREFIX. Engine and STEP scripts stamp automatically; the manual workflow stamps preview after compilation. For a separately orchestrated preview build, export `ORCA_BUILD_SOURCE="$(node wasm/scripts/runtime-manifest.mjs fingerprint)"` before compiling, then run `node wasm/scripts/runtime-manifest.mjs create preview <runtime-dir>` after successful compilation with the actual WASM_PREFIX exported. A stamp is build evidence, not a cryptographic signature or an independently reproducible-build claim; never stamp an old binary to bypass rejection.

Vite requires all three manifests and runtime asset sets for production packaging, and verifies copied bytes again. Explicit ORCA_ENGINE_DIR, ORCA_PREVIEW_DIR and ORCA_STEP_MODULE_DIR still select developer inputs; dev serving does not stamp or qualify them. Production has no missing-asset bypass. Docker copies the manifest and source inputs and verifies through the same Vite gate. Preview remains the existing worker-compatible `orca_preview.js`/`.wasm` runtime; the replacement parser contract uses these same assets, with no additional runtime bundle. Final builders must stamp only after native feature sources settle.
