Images are plain img without crossorigin or credentialless attributes. There is no automatic reload. Direct errors or oversized decoded images retry the relay once; relay failures retain placeholders. JFIF always uses relay because its CDN response ignores the transform.

Both upstream paths use exactly `x-oss-process=image/resize,m_lfit,w_300,h_300/format,webp`. Caller queries are rejected. Relay additionally decodes the first raster frame and fits within 300×300 using installed `/usr/bin/convert`, preserving aspect ratio, stripping metadata and emitting WebP. Decode has process timeout/resource/output limits; failures are not cached. This adds an ImageMagick runtime dependency on the private host. The versioned `/_model-thumbnail/v300` route prevents old cached 400px responses from violating the new bounds; the legacy route remains compatible for previously loaded clients.

All static responses, including hashed workers and 304 responses, carry User-Agent and Accept-Encoding Vary before validators. Document and worker policies use the same selection. Successful normalized relay images retain bounded cache/public five minute TTL; errors no-store.
