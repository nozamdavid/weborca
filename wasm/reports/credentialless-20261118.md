# Credentialless opt-in qualification — 2026-11-18

The implementation and immutable candidate are staged. Private :18974 was tested briefly, then restored to its existing require-corp preview. Production was never changed. Overall rollout is **unqualified**: Safari/iOS and Firefox Android do not support credentialless according to current [MDN browser compatibility data](https://github.com/mdn/browser-compat-data/blob/main/http/headers/Cross-Origin-Embedder-Policy.json), captured in [browser-compat.json](credentialless-20261118/browser-compat.json). A relay fallback restores images, but cannot restore cross-origin isolation when a browser ignores the document policy. A compatibility-aware document policy is required before wider private rollout.

`ORCA_COEP=credentialless` opts the staging server in; `VITE_COEP=credentialless` opts Vite dev/preview and the built thumbnail UI in. Both default to require-corp and reject other configured values. Keep these settings paired. Without UI opt-in or crossOriginIsolated, images use the existing relay. Direct errors retry the relay once; relay errors retain the placeholder. Actual img uses the exact makerworld.bblmw.com public model/design raster allowlist with the literal fixed `?x-oss-process=image/resize,w_400/format,webp` transform, no crossorigin, no referrer. Login, cloud, byte relay and native worker code were preserved.

[Chrome primary documentation](https://developer.chrome.com/blog/coep-credentialless-origin-trial) confirms Chrome 96 support, no-CORS credential omission and isolation with COOP same-origin. [MDN header documentation](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Cross-Origin-Embedder-Policy) confirms CORS requests still require CORS permission. This differs from credentialless iframes. No service worker implementation or registration was found in the app, and the real private browser reports controller null. Vite's file middleware, dev and preview headers were inspected and made opt-in; existing auth/gateway-specific conservative headers remain.
